# 数据结构与更新接口

> 本文描述 **MySQL**（交易数据权威库）与 **Qdrant**（语义检索库）中的数据结构格式与参数，
> 并约定一组**更新接口**用于维护两侧数据。
>
> 存储划分（详见 [PROJECT.md](../PROJECT.md)）：
> - **MySQL**：4 张表 —— `customer` / `product`(纯库存) / `orders` / `after_sale`。
> - **Qdrant**：商品详情 / 售后知识**分库存储**，两个独立 collection —— `digital_cs_products`（商品）/ `digital_cs_knowledge`（知识）；集合本身即数据分区，不再靠 payload.type 过滤。
> - 商品按 `productNo` 跨库关联：MySQL 存库存，Qdrant 存价格与详情。

## 一、MySQL 数据结构

字符集统一 `utf8mb4`，引擎 `InnoDB`。下表「Java 字段」对应 `entity/` 中实体（驼峰），数据库列为下划线。

| `id` | `id` | BIGINT | PK, AUTO_INCREMENT | 主键 |

| `nickname` | `nickname` | VARCHAR(64) | NULL | 昵称 |

| `created_at` | `createdAt` | DATETIME | NOT NULL, 默认 now | 创建时间 |

## 二、Qdrant 数据结构

- **Collection（分库存储）**：商品详情 `digital_cs_products`、售后知识 `digital_cs_knowledge`（均走 gRPC 端口 6334）。
  集合名可由 `app.qdrant.product-collection` / `app.qdrant.knowledge-collection` 配置；`VectorSearchService` 按 `type` 映射到对应集合。
- **命名向量**（两个集合结构一致）：
  - `dense`：DashScope `text-embedding-v3`，**1024 维**，距离 `COSINE`（语义检索；未配置真实 key 时关闭）。
  - `sparse`：jieba 分词词频向量，modifier `IDF`（关键词检索，服务端算 IDF；恒可用）。
- **Point ID**：由 `type:bizId` 派生的稳定 UUID（`UUID.nameUUIDFromBytes("product:P10001")`），保证重灌库覆盖同条而非新增。
- **公共 payload 字段**：
  - `type`：`product` | `knowledge`，随 payload 写入仅作溯源（检索分区已由集合承担，不再用于过滤）。
  - `bizId`：业务主键。商品=`productNo`；知识=种子数组序号（1 起）。
- **嵌入文本**（参与向量化，不单独存）：商品=名称+副标题+分类+品牌+描述+规格；知识=标题+正文+关键词。
- **payload 写入规则**：所有值以**字符串**写入；嵌套结构（如 `specs`）序列化为 **JSON 字符串**。

### 1. `type = product` 商品详情 payload

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | String | 固定 `product` |
| `bizId` | String | 商品编号 = `productNo`（回 MySQL 补库存的关联键） |
| `name` | String | 商品名称（权威源） |
| `subtitle` | String | 副标题 |
| `category` | String | 分类，如 `手机`（检索时作 payload 等值过滤下推） |
| `brand` | String | 品牌，如 `华为`（检索时作 payload 等值过滤下推） |
| `price` | String(数值) | 售价（元，字符串存储，合并时解析为 BigDecimal） |
| `marketPrice` | String(数值) | 市场价/划线价 |
| `publishedAt` | String(日期) | 发布时间 `YYYY-MM-DD`（无 query 时按此倒序） |
| `description` | String | 商品描述 |
| `specs` | String(JSON) | 规格参数数组的 JSON 字符串：`[{"name":"处理器","value":"A17 Pro"}]` |

**种子样例**（`seed/products.json`，灌库前的原始格式，`specs` 为数组对象）：

```json
{
  "productNo": "P10001",
  "name": "极客Pro X1 旗舰手机",
  "subtitle": "6.7英寸 5000mAh 长续航",
  "category": "手机",
  "brand": "极客Pro",
  "price": 3999.00,
  "marketPrice": 4299.00,
  "publishedAt": "2024-03-01",
  "description": "极客Pro X1 搭载旗舰处理器……",
  "specs": [ { "name": "处理器", "value": "旗舰8核" } ]
}
```

### 2. `type = knowledge` 售后知识 payload

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | String | 固定 `knowledge` |
| `bizId` | String | 序号（种子数组下标 +1） |
| `kbType` | String(数值) | 知识类别：**1**机型专项 **2**通用售后 |
| `title` | String | 标题（检索结果 text 取此） |
| `content` | String | 正文/解决方案 |
| `keywords` | String | 关键词（空格分隔，增强 sparse 召回） |

**种子样例**（`seed/knowledge.json`）：

```json
{
  "kbType": 2,
  "title": "如何申请7天无理由退货？",
  "content": "签收后7天内，商品保持完好可在订单详情页申请……",
  "keywords": "退货 7天 无理由 退款"
}
```

## 三、更新接口（预留）

> 现有运维端点仅 `POST /admin/reindex`（从种子 JSON **全量重灌** Qdrant）。
> 下列为**预留的增量更新接口约定**，用于运维侧维护 MySQL 与 Qdrant 数据。
> 路由前缀沿用 `IndexAdminController` 的 `/admin`，统一返回 `{ ok, affected, message }`。
>
> ⚠️ 当前仓库尚未实现这些 Controller，本节为接口设计契约。需要落地时按本约定在 `web/` 下新增控制器即可。

### MySQL 侧

#### 1. 更新商品库存 / 状态 — `PUT /admin/product/{productNo}`

更新 `product` 表的库存与上下架状态（价格/详情请走 Qdrant 接口）。

```json
// Request Body
{ "stock": 100, "status": 1, "name": "极客Pro X1 旗舰手机" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `stock` | Integer | 否 | 可用库存（非负） |
| `status` | Integer | 否 | 0下架 1在售 |
| `name` | String | 否 | 展示名兜底 |

> 实现：`new LambdaUpdateWrapper<Product>().eq(Product::getProductNo, productNo)` 仅更新非空字段。

#### 2. 更新订单状态 / 物流 — `PUT /admin/order/{orderNo}`

```json
{
  "orderStatus": 2,
  "payStatus": 1,
  "logistics": { "company": "顺丰速运", "trackingNo": "SF...", "status": 2,
    "traces": [ { "time": "2026-06-01 10:00", "location": "上海揽收点", "description": "已揽收" } ] }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `orderStatus` | Integer | 否 | 0待付款 1待发货 2待收货 3已完成 4已取消 |
| `payStatus` | Integer | 否 | 0未付 1已付 2已退款 |
| `logistics` | Object | 否 | 整体覆盖物流 JSON（结构同 §一.3） |

#### 3. 更新售后单状态 — `PUT /admin/after-sale/{afterSaleNo}`

```json
{ "status": 1, "remark": "审核通过，等待寄回" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `status` | Integer | 否 | 0待审 1已通过 2已拒绝 3处理中 4已完成 |
| `remark` | String | 否 | 处理备注 |

#### 4. 更新客户资料 — `PUT /admin/customer/{customerNo}`

```json
{ "nickname": "张三", "phone": "13800001111", "memberLevel": 2 }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `nickname` | String | 否 | 昵称 |
| `phone` | String | 否 | 手机号 |
| `memberLevel` | Integer | 否 | 0普通 1银 2金 3铂金 |

### Qdrant 侧（商品详情 / 价格 / 知识库）

> 复用 `VectorSearchService.index(type, List<Record>)`：按 `type:bizId` 派生稳定 UUID **upsert**，
> 已存在则覆盖、不存在则新增；同时重算 sparse（恒有）+ dense（嵌入可用时）向量。

#### 5. upsert 单条商品详情 — `PUT /admin/qdrant/product/{productNo}`

Body 同 `seed/products.json` 单条结构（`specs` 为数组对象）。服务端拼接嵌入文本、组装 payload 后 upsert。

```json
{
  "name": "...", "subtitle": "...", "category": "手机", "brand": "极客Pro",
  "price": 3999.00, "marketPrice": 4299.00, "publishedAt": "2024-03-01",
  "description": "...", "specs": [ { "name": "处理器", "value": "旗舰8核" } ]
}
```

> `bizId` 取路径 `{productNo}`；价格/发布时间仅入 payload，不进嵌入文本。

#### 6. upsert 单条知识 — `PUT /admin/qdrant/knowledge/{bizId}`

```json
{ "kbType": 2, "title": "如何申请7天无理由退货？", "content": "……", "keywords": "退货 7天 无理由 退款" }
```

#### 7. 删除单条向量 — `DELETE /admin/qdrant/{type}/{bizId}`

按 `type` 定位集合、`type:bizId` 派生 UUID 删除对应 point（`type` ∈ `product` / `knowledge`）。
> 需在 `VectorSearchService` 增补 `delete(type, bizId)`（`qdrantClient.deleteAsync` + 同款 `stableUuid`）。

## 四、关联与一致性要点

- **商品跨库**：`productNo` 是 MySQL `product` 与 Qdrant `digital_cs_products` 的关联键。改价格/详情 → Qdrant；改库存/上下架 → MySQL。两侧 `productNo` 必须一致，否则搜索召回后回 MySQL 补库存会缺失。
- **售后知识**：纯 Qdrant `digital_cs_knowledge` 承载，无 MySQL 镜像，检索直接取 payload。
- **降级**：未配置真实 DashScope key（或以 `sk-dummy` 开头）时 dense 关闭，检索退化为纯 sparse 关键词；Qdrant 不可用时检索返回空、写入/更新跳过（仅记日志），MySQL 查询不受影响。
- **权威源**：Qdrant 数据的初始权威源是 classpath 种子 JSON；§三 的增量更新接口落地后，运维变更应同步回写种子 JSON，以免下次 `/admin/reindex` 全量重灌时被覆盖。
