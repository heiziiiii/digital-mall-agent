# MCP 工具说明

这份文档说明各 MCP 工具适合在什么客服场景下使用。描述面向大模型 Agent，重点放在能力边界和调用时机，不展开后端实现。

## 订单工具

### queryOrder

查询指定订单的商品明细、订单状态、物流概况和关联售后。客户已提供订单号，或围绕某一笔订单询问买了什么、进展到哪、是否发货等问题时使用；没有订单号时先用 `listCustomerOrders` 定位。

### listCustomerOrders

列出当前客户的订单记录，用来从近期订单、某段时间、某个商品等线索中找到目标订单。客户确认具体订单后，再用 `queryOrder` 查详情，或用 `trackLogistics` 查物流。

### trackLogistics

查询指定订单的发货状态和物流轨迹。客户关心快递到哪了、是否发货、什么时候能到时使用；如果还需要订单内容、付款状态或售后概况，改用 `queryOrder`。

### createOrder

为当前客户创建一笔待付款订单。客户明确决定购买某个商品时使用；调用前必须确认商品编号、购买数量、收货人、手机号和收货地址。该写操作需要用户先核对确认，确认后才会真正扣减库存并生成订单；不要承诺已付款或已发货。

## 售后工具

### queryAfterSale

查询指定售后单的类型、原因和处理进度。客户已提供售后单号，或追问某次退款、换货、维修进展时使用；如果客户说不出售后单号，先通过订单或客户售后列表帮他定位。

### listOrderAfterSales

查询某个订单关联的售后记录。客户围绕一笔订单询问退款、退换货、维修记录，或准备再次申请售后前需要确认已有申请时使用；要看单条售后进度时再用 `queryAfterSale`。

### listCustomerAfterSales

列出当前客户的售后申请。客户笼统询问自己的售后、退款或申请记录时使用；客户选定某一条后，再用 `queryAfterSale` 查看详情。

### createAfterSale

为客户的订单提交售后申请，支持退货退款、换货、仅退款和维修。只在客户明确要办理售后时使用；调用前先确认订单号、售后类型和原因，调用后说明已提交处理，不要承诺审核结果或到账时间。

### createHumanService

创建人工服务单。仅当客户明确要求人工客服、投诉升级、情绪明显不满，或问题经客服/工具处理后仍难以解决时使用；调用前先确认转人工原因，可选关联订单号。售后申请单号由 createAfterSale 后端生成，不由用户或模型填写；不要承诺人工响应时效或处理结果。

## 商品工具

### searchProducts

按客户需求检索本店数码商品，支持目标商品短语、类目、品牌、预算和排序。`query` 应是面向 RAG/向量检索的目标产品词，例如 `三星高端旗舰手机`、`华为长续航手机`，不要写 `用户想找`、`优先推荐` 这类指导性话语。适合找商品、推荐商品、筛选或对比候选款；客户已明确商品编号并追问价格、库存或规格时，改用 `getProductDetail`。

### getProductDetail

查询指定商品的价格、库存、品牌、类目和规格等详情。客户已明确商品编号后追问多少钱、有没有货、参数如何时使用；如果客户只是模糊描述想买什么，先用 `searchProducts` 找候选。

## 知识库工具

### searchKnowledge

检索通用客服知识，用于回答产品使用、故障排查、保养建议、售后政策和流程说明。适合不依赖具体订单、库存或个人售后状态的问题；如果客户转为查询个人订单、物流、售后或提交申请，应切换到对应业务工具。
